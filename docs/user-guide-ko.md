# MediaWorks 한국어 사용 매뉴얼

작성 기준일: 2026-05-23

이 문서는 MediaWorks를 사용하는 상품기획자, MD, 리서치 담당자, 제작 담당자를 위한 업무 매뉴얼이다. 화면에서 무엇을 보고 어떤 순서로 판단하면 되는지를 설명한다.

## 1. MediaWorks로 하는 일

MediaWorks는 내부 홈쇼핑 상품/매출 데이터와 경쟁 홈쇼핑/방송 데이터를 함께 보고 다음 결정을 돕는 시스템이다.

1. 어떤 상품군이 우리에게 잘 맞는지 확인한다.
2. 현재 시장과 경쟁 방송에서 어떤 상품이 움직이는지 확인한다.
3. 새로 팔 만한 상품 후보를 발굴한다.
4. 후보 상품의 소싱 가능성, 도매가, 방송 적합성을 심화 확인한다.
5. 좋은 후보를 Research 상품으로 승격한다.
6. Research 리포트와 MD 전략으로 판매 방향을 정한다.
7. 방송 대본을 만들어 실제 판매 실행물로 연결한다.

가장 기본적인 사용 흐름은 다음과 같다.

```text
상태 확인 -> 후보 발굴 확인 -> 관심 후보 심화 조사 -> Research 승격 -> MD 전략 생성 -> 방송 대본 생성
```

## 2. 주요 메뉴

| 메뉴 | 용도 |
| --- | --- |
| 자사 | 내부 상품, 매출, 카테고리 성과를 확인한다. |
| 시장 | 경쟁 방송 편성, OA 방송 데이터, 시장 흐름을 확인한다. |
| 신규 상품 발굴 | 홈쇼핑/라이브 커머스용 신상품 후보를 검토한다. |
| 신규 상품 추천 | 내부 실적과 외부 후보를 바탕으로 MD 전략을 만든다. |
| 연결 상태 | 추천 흐름이 정상적으로 이어지는지 확인한다. |
| 제작 | Research 상품에 연결된 방송 대본을 확인하고 수정한다. |
| 관리 | 사용자, 권한, 운영 상태를 확인한다. |

한국어 화면은 `/ko` 경로를 사용하고, 일본어 화면은 `/ja` 경로를 사용한다.

## 3. 하루 업무 루틴

### 3.1 먼저 연결 상태 확인

아침에 가장 먼저 `시장 > 연결 상태` 화면을 확인한다.

정상 상태라면 다음과 같이 보인다.

- `연결 정상`
- `모든 체크 통과`

이 화면에서 문제가 보이면, 그날의 추천 결과를 만들기 전에 어떤 단계가 빠졌는지 먼저 확인한다.

주요 체크 항목은 다음과 같다.

- 홈쇼핑 발굴이 완료됐는지
- 라이브 커머스 발굴이 완료됐는지
- Research로 승격 가능한 후보가 있는지
- Research 결과가 생성됐는지
- MD 전략이 내부 실적과 외부 후보를 함께 사용했는지
- Research 상품에 연결된 방송 대본이 있는지
- 방송/카테고리 근거 데이터가 충분한지

### 3.2 홈쇼핑 후보 확인

`시장 > 신규 상품 발굴 > 홈쇼핑` 화면으로 이동한다.

확인할 내용:

- 오늘의 후보가 충분히 생성됐는지
- 상품명이 명확한지
- 가격대가 홈쇼핑 판매에 맞는지
- 리뷰 수와 평점이 참고할 만한지
- TV 적합도 설명이 설득력 있는지
- 이미 판매 중인 상품이나 중복 상품은 아닌지
- 경쟁 방송 또는 OA 방송 신호가 있는지

후보별로 다음 판단을 남긴다.

| 액션 | 의미 |
| --- | --- |
| 소싱됨 | 실제 소싱 대상으로 결정한 상품 |
| 관심 있음 | 지금 당장 결정하지 않지만 다시 볼 가치가 있는 상품 |
| 거절 | 우리 방향과 맞지 않는 상품 |
| 이미 있음 | 이미 보유 중이거나 중복인 상품 |

판단을 남기면 이후 발굴과 추천 품질을 개선하는 데 활용된다.

### 3.3 라이브 커머스 후보 확인

`시장 > 신규 상품 발굴 > 라이브 커머스` 화면으로 이동한다.

라이브 커머스 후보는 홈쇼핑 후보와 다르게 다음 관점으로 본다.

- 짧은 시간 안에 장점이 보이는가
- 시연 장면이 명확한가
- 댓글과 질문을 유도하기 쉬운가
- 가격 설명이 복잡하지 않은가
- 출연자가 사용 장면을 쉽게 보여줄 수 있는가

라이브에서 보여주기 어려운 상품은 홈쇼핑에 더 적합할 수 있으므로, 무조건 거절하지 말고 판매 채널 적합성을 나누어 판단한다.

## 4. 후보 상품 심화 조사

관심 있는 후보는 심화 조사를 실행한다. 심화 조사는 후보를 단순 아이디어에서 실제 검토 가능한 상품으로 바꾸는 단계다.

심화 조사 결과에서 확인할 내용:

- 제조사 또는 공급사 단서
- 도매가와 예상 마진
- 최소 주문 수량이나 공급 조건 단서
- 방송에서 강조할 수 있는 포인트
- SNS나 시장 반응 신호
- 홈쇼핑 또는 라이브 커머스 시연 가능성

심화 조사가 완료된 후보는 Research 상품으로 승격할 수 있다.

## 5. Research 상품으로 승격

심화 조사 결과가 충분하고 실제 검토 가치가 있다고 판단되면 후보를 Research 상품으로 승격한다.

승격 전 확인할 것:

- 상품명이 명확한가
- 상품 URL 또는 판매처 단서가 있는가
- 가격대가 현실적인가
- 방송에서 설명할 장점이 있는가
- 내부 상품군과 충돌하지 않는가
- 소싱 가능성이 완전히 낮지는 않은가

승격 후에는 정식 Research 리포트가 생성되고, 해당 상품은 MD 전략과 방송 대본 생성에 연결된다.

## 6. Research 리포트 확인

Research 상품 상세 화면에서 리포트를 확인한다.

중점적으로 볼 항목:

- 일본 시장에서 팔릴 가능성
- 주요 고객층
- 가격대와 경쟁 상품
- 상품의 차별점
- 홈쇼핑/라이브 커머스 판매 적합성
- 경쟁 방송 또는 시장 데이터 근거
- 리스크와 보완점

Research 리포트는 최종 결정서가 아니라, MD 전략과 대본 생성을 위한 근거 자료다. 리포트에서 가능성이 보이면 전략 생성으로 넘어간다.

## 7. MD 전략 생성

`시장 > 신규 상품 추천` 화면에서 MD 전략을 생성한다.

MD 전략은 다음 질문에 답한다.

- 어떤 상품을 우선 추천할 것인가
- 왜 그 상품이 현재 시장에 맞는가
- 내부 실적과 어떤 관련이 있는가
- 어떤 채널에서 팔아야 하는가
- 어떤 가격과 마진 구조가 적절한가
- 어떤 마케팅 메시지를 써야 하는가
- 예상 매출과 리스크는 무엇인가

전략 결과에서 반드시 확인할 것:

- 추천 상품 목록
- 각 상품의 추천 이유
- 내부 실적 근거
- 외부 후보 근거
- TV/OA 방송 신호
- 가격/마진 제안
- 판매 채널 제안
- 실행 리스크

전략 상세 화면 상단에는 내부 실적, 외부 후보, 방송 신호, Discovery 연결 여부가 요약된다. 이 영역을 먼저 보고 전략이 충분한 근거를 사용했는지 판단한다.

## 8. 라이브 커머스 전략

라이브 커머스 전략은 홈쇼핑 MD 전략과 별도로 본다.

확인할 내용:

- 어떤 플랫폼에 적합한가
- 어떤 콘텐츠 구성이 좋은가
- 진행자가 어떤 순서로 보여줘야 하는가
- 실시간 질문에 답하기 쉬운 상품인가
- 할인, 세트, 한정 수량 같은 라이브 장치가 필요한가
- 실패할 경우 어떤 대안을 둘 수 있는가

라이브 커머스 전략은 단순 상품 추천보다 콘텐츠 운영 계획에 가깝다.

## 9. 방송 대본 생성

Research 상품 상세 화면에서 방송 대본을 생성한다.

대본 생성 후 확인할 것:

- 첫 30초 안에 상품의 핵심 장점이 드러나는가
- 문제 제기와 해결 구조가 자연스러운가
- 시연 장면이 구체적인가
- 가격과 혜택 설명이 명확한가
- 고객층에 맞는 말투인가
- 과장 표현이나 검증되지 않은 표현은 없는가
- MD 전략에서 강조한 포인트가 대본에 반영됐는가

대본은 `제작` 메뉴에서 다시 확인하고 수정할 수 있다.

### 대본의 근거를 확인하는 법 (2026-09-05)

대본은 이제 "무엇을 근거로 썼는지"를 함께 저장한다. 대본 화면 왼쪽 탭에서 확인한다.

- **사실** — 이 대본이 말해도 되는 사실 목록. 각 항목에 `단정 가능` / `출처 명시` / `구성 전용` 배지가 붙는다.
  - `단정 가능`: 자사 입력이나 검증된 값. 그대로 말해도 된다.
  - `출처 명시`: 제조사 주장. "메이커에 따르면"을 붙여야 한다.
  - `구성 전용`: 방송 횟수 같은 대리 지표. **방송에서 말하면 안 된다.** 구성을 정할 때만 쓴다.
  - 아래의 `부족한 데이터`가 핵심이다. 여기 적힌 항목은 대본이 언급하지 않도록 금지되어 있다.
- **참조** — 구성 참고로 읽은 경쟁 방송과, 경쟁 구성 데이터를 쓰지 못한 이유.
  - `대상 외 카테고리` / `분석된 방송이 부족` / `시간 초과` 등으로 이유가 명시된다.
    아무 표시가 없던 예전과 달리, 왜 반영되지 않았는지 알 수 있다.
- **구성 / 실연** — 대본을 쓰기 전에 확정한 진행 순서와 척 배분, 실연 계획.
  지시한 필수 실연이 빠지지 않았는지 여기서 확인한다.
- **주장** — 대본 안의 사실 주장과 그 근거. `확인 필요`가 맨 위에 온다.
  - **`확인 필요` 항목은 방송 전에 사람이 반드시 확인해야 한다.** 근거가 없는 수치·효과 표현이다.
  - 항목을 클릭하면 대본의 해당 줄로 이동한다.

기능 도입(2026-09-05) 이전에 만든 원고와 Word에서 가져온 원고에는 이 정보가 없다.
그런 원고는 "생성 컨텍스트가 없습니다"라고 표시된다 — 확인이 끝났다는 뜻이 아니다.

상품 파인더 결과 카드의 `台本を作成`을 누르면 그 상품의 축적 데이터를 근거로 대본 생성이 시작된다.

## 10. 시장/방송 데이터 확인

`시장 > 방송 캘린더`에서는 경쟁 방송 데이터를 확인한다.

활용 방법:

- 최근 QVC와 Shop Channel에서 어떤 상품군을 편성했는지 본다.
- 같은 카테고리 상품이 반복적으로 노출되는지 확인한다.
- OA 방송에서 주목할 만한 상품 흐름이 있는지 본다.
- 우리 추천 상품과 유사한 상품이 이미 방송되고 있는지 확인한다.
- 경쟁사가 강조하는 가격, 구성, 세일즈 포인트를 참고한다.

방송 데이터는 단순 참고 자료가 아니라 Discovery, Research, MD Strategy의 근거로 사용된다.

## 11. 내부 매출 데이터 확인

`자사` 메뉴에서는 내부 상품과 매출 성과를 본다.

확인할 내용:

- 어떤 카테고리가 잘 팔렸는가
- 어떤 가격대가 성과가 좋았는가
- 마진이 좋은 상품군은 무엇인가
- 특정 시즌에 강한 상품군은 무엇인가
- 주차별 판매 흐름이 안정적인가
- 신규 추천 상품이 기존 강점과 연결되는가

MD 전략을 볼 때는 반드시 내부 실적 근거가 함께 사용됐는지 확인한다.

## 12. 추천 결과 판단 기준

추천 상품을 볼 때는 다음 순서로 판단한다.

1. 내부 실적과 연결되는가
2. 현재 경쟁 방송 또는 시장 흐름과 연결되는가
3. 가격대가 홈쇼핑/라이브 커머스에 맞는가
4. 시연하거나 설명하기 쉬운가
5. 공급 가능성 또는 판매처 단서가 있는가
6. 고객층이 명확한가
7. 방송 대본으로 만들었을 때 설득력이 있는가

한두 항목만 좋은 상품보다, 여러 항목이 균형 있게 맞는 상품을 우선 검토한다.

## 13. 상태 화면에서 문제가 보일 때

`연결 상태` 화면에서 `확인 필요` 또는 실패 항목이 보이면 다음 순서로 본다.

| 문제 영역 | 사용자가 볼 내용 | 다음 행동 |
| --- | --- | --- |
| 홈쇼핑 발굴 | 최신 후보가 없거나 완료되지 않음 | 잠시 후 다시 확인하거나 관리자에게 발굴 상태 확인 요청 |
| 라이브 발굴 | 라이브 후보가 없거나 완료되지 않음 | 라이브 발굴 완료 여부 확인 요청 |
| C 패키지 | Research로 올릴 만큼 조사된 후보가 없음 | 관심 후보를 심화 조사 |
| Research | 승격 상품의 리포트가 없음 | 리포트 생성 상태 확인 요청 |
| MD 전략 | 내부 실적과 외부 후보가 함께 쓰이지 않음 | 전략을 다시 생성하거나 후보/조건 조정 |
| 방송 대본 | Research 상품에 연결된 대본이 없음 | 상품 상세에서 대본 생성 |
| 데이터 근거 | 방송/카테고리 근거가 부족함 | 결과 해석 시 보수적으로 판단하고 관리자에게 데이터 보강 요청 |

사용자는 화면에서 문제 영역을 확인하고, 필요한 경우 관리자나 시스템 담당자에게 해당 항목을 전달하면 된다.

## 14. 주간 리뷰

주 1회 다음을 확인한다.

- 이번 주 소싱됨 처리한 상품
- 관심 있음으로 남긴 상품
- 거절이 많았던 카테고리
- 잘 맞는 가격대
- 반복적으로 등장한 방송 카테고리
- MD 전략에서 자주 추천된 상품군
- 실제 소싱/판매 검토로 이어진 상품

주간 리뷰의 목적은 다음 주 발굴 방향을 조정하는 것이다.

예시 판단:

- 특정 카테고리에서 계속 거절이 많으면 발굴 방향을 줄인다.
- 특정 가격대 후보가 반복적으로 좋으면 그 범위를 우선 검토한다.
- 방송 신호는 강하지만 내부 실적과 약하면 테스트 판매 대상으로 본다.
- 내부 실적은 좋지만 외부 신호가 약하면 보수적으로 접근한다.

## 18. 데이터 인텔리전스 파이프라인 운영 (관리자)

이 파이프라인은 수집한 상품과 방송 정보를 정규화하고, 출처와 관찰 시점이 있는 근거와 인사이트로 계속 쌓아 둔다. 상품 추천, Research, 취급 상품 선택, 방송 대본은 사용자가 요청할 때 이 저장 데이터를 활용해 만드는 결과물이다. 백필이나 인사이트 갱신이 추천·Research·선택·대본을 자동 생성하지는 않는다.

최근 데이터의 백필 예상량만 확인하려면 먼저 쓰기 없는 dry-run을 실행한다.

```bash
npm run backfill:intelligence -- --since=2026-08-01 --limit=200
```

출력의 `write=false`, source별 읽은 행 수, 예상 근거 수, 검토가 필요한 카테고리를 확인한다. 적용할 때만 `--apply`를 붙인다.

```bash
npm run backfill:intelligence -- --since=2026-08-01 --limit=200 --apply
```

한 번의 실행은 source별 200행이 기본값이며, `--limit` 은 최대 2,000행까지 지정할 수 있다. 출력의 `nextCursor`가 문자열이면 같은 `--since`, `--limit`과 함께 정확히 다시 전달한다. `nextCursor`가 `null`일 때 해당 범위가 끝난다.

```bash
npm run backfill:intelligence -- --since=2026-08-01 --limit=200 --cursor='<nextCursor>' --apply
```

적용과 인사이트 갱신 후에는 읽기 전용 검증을 실행한다.

```bash
npm run verify:intelligence-foundation
```

검증 결과는 additive migration, 최근 pipeline 시도, canonical link, 최근 활성 상품의 카테고리 커버리지, 근거 수, 인사이트-근거 링크 수 일치, known/non-known 값 정합성을 확인한다. `rawActive`는 최신 성공 Discovery 세션의 활성 후보 전체이고, `eligible`은 현재 QVC·Shop Channel·연결된 OA source 범위에서 백필 가능한 후보 수다. 방송 분석 커버리지도 실제 수치로 함께 출력되지만 추천이나 대본 생성 건수를 요구하지 않는다.

파이프라인 화면의 상태 의미는 다음과 같다.

| 상태 | 의미 |
| --- | --- |
| 정상 | 최근 성공 실행이 source별 허용 시간 안에 있음 |
| 일부 저하 | 최근 시도가 부분 완료. 동작은 하지만 확인이 필요함 |
| 실행 중 | 최근 시도가 진행 중이고 heartbeat가 최신임 |
| 기한 초과 | 성공 기록은 있지만 허용 시간보다 오래됨 |
| 실패 | 최근 시도가 실패했거나, 30분 넘게 heartbeat가 없는 실행 중 상태. 이전 성공으로 가리지 않음 |
| 미실행 | 새 정규화 run이 아직 없거나 해당 작업을 아직 실행하지 않음 |

근거의 중복 키 정의를 바꾼 경우에는 다음 백필 전에 한 번 재계산을 실행한다. 실행하지 않으면 같은 사실이 새 행으로 중복 적재된다. 쓰기 없이 차이를 확인한 뒤 `--apply` 를 붙인다.

```bash
npm run rekey:intelligence-evidence
npm run rekey:intelligence-evidence -- --apply
```

인사이트 갱신은 JST 05:00 크론으로 자동 실행된다. 위 백필은 과거 데이터를 채우거나 장애에서 복구할 때 쓰는 수동 작업이다.

분모가 없는 비율은 `0%`가 아니라 `—`로 표시한다. 추천, Research, 취급 상품 선택, 대본이 0건이어도 아직 요청하지 않은 상태라면 파이프라인 실패가 아니다.

### ShopCh 방송 분석 대량 처리 (서울 EC2)

ShopCh는 한 편이 약 1.16GB(57분)라 3.1TB 전체를 로컬로 내려받으면 전송비만 약 $345 든다. 버킷이 `ap-northeast-2`에 있으므로 같은 리전 EC2에서 돌리면 전송비가 0이 된다.

```bash
# 1) 복원 (Bulk, 48시간, 약 $26)
npm run restore:archives -- --channel=shopch --category=コスメ --tier=Bulk --days=7 --apply

# 2) 완료 확인
npm run restore:archives -- --channel=shopch --category=コスメ --status

# 3) 서울 EC2에서 드레인
bash scripts/drain-shopch-ec2.sh
```

3번 스크립트는 리전을 확인하고 `ap-northeast-2`가 아니면 실행을 거부한다. 실수로 로컬에서 돌려 $345를 쓰는 것을 막기 위한 장치다. 필요한 것은 인스턴스 역할의 `s3:GetObject` 권한과 레포 루트의 `.env.local`이다.

드레인 스크립트는 각 카테고리의 첫 배치에서 `--reset=cold_storage` 를 함께 실행한다. 복원 전에 크론이 집었다가 `cold_storage` 로 포기한 슬롯들은 시도 횟수가 소진돼 큐에서 빠져 있는데, 이 리셋이 없으면 복원이 끝나도 그 슬롯들은 영영 분석되지 않는다. 리셋은 `--channel` 과 `--category` 양쪽으로 스코프되므로 드레인 중인 카테고리 밖으로 번지지 않는다.

**복원이 끝나기 전에 드레인을 시작하지 말 것.** 아직 해동되지 않은 슬롯은 `cold_storage`로 스킵 처리되고 그 기록이 남아, 분석 없이 백로그만 소진된다.

작업이 끝나면 **인스턴스를 반드시 정지 또는 종료**한다. 유휴 상태에서도 초 단위로 과금된다.

## 19. 상품 파인더 (축적 데이터 기반)

`/analytics/product-finder` 는 **이미 쌓인 증거만 읽어** 상품 순위를 매긴다. 새로 검색하지 않으므로 실행에 추가 비용이 들지 않고, 결과는 언제든 같은 근거로 재현된다.

### 다섯 개의 축

| 축 | 무엇을 보는가 | 근거 |
|---|---|---|
| 시장 수요 | 타 채널 방영 횟수, 최근 방영, 리뷰 수 | 대리 지표 |
| 자사 적합 | 지정 가격대 적합, 내부 마진율 | 사내 입력이 있을 때만 |
| 수익성 | 공헌이익 | **사내 원가 데이터가 있을 때만** |
| 경쟁 여지 | 경쟁사 방영이 적을수록 높음 | 대리 지표 |
| 방송 적합 | 분석 완료된 참고 방송의 양 | 추론 |

각 축에는 **확인됨 / 대리 지표 / 데이터 없음** 배지가 붙는다. 같은 60점이라도 사내 원가에서 나온 60점과 방영 횟수에서 추정한 60점은 다른 것이며, 배지가 그 차이를 말한다.

### 수익성이 비어 있는 이유

`판단 자료 부족` 은 "수익이 0" 이 아니라 **"계산할 내부 데이터가 없다"** 는 뜻이다. 공헌이익은 우리 원가로만 계산하며, 경쟁사가 광고에서 말한 매출은 우리 마진이 아니므로 절대 대입하지 않는다.

내부 원가는 엑셀 취입 기능(다음 단계)으로 들어온다. 그전까지 이 축은 모든 상품에서 비어 있는 것이 정상이다.

### 경쟁사 매출이 표시되지 않는 이유

경쟁사가 "누적 10만 대 돌파" 라고 말했다면 그것은 **외부 주장(source_claim)** 으로 저장되며, 실제 판매량으로 승격되지 않는다. 공식 출처가 직접 밝힌 수치가 아닌 한 매출·판매량으로 쓰지 않는다는 원칙이다.

### 결과를 읽는 법

- **종합 지표** 는 수익성을 뺀 네 축의 가중 평균이다. 수익성은 성격이 다른 값이라 섞지 않고, 알려진 경우 **정렬에서 먼저** 적용된다.
- **증거 커버리지** 가 낮으면 순위의 확도가 낮다. 커버리지 30% 미만은 `확도: 낮음` 으로 표시된다.
- **부족한 데이터** 항목은 숨기지 않고 나열한다. 화면에서 사라진 축은 "관계없음" 으로 읽히기 때문이다.
- `관심 있음` / `제외` 는 **메모일 뿐** 이며, 조사나 대본 생성을 자동으로 시작하지 않는다.
