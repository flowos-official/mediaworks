### 2. 데이터에서 실제 사업 인사이트가 나오고 있다

- 내부 의료기기 분류는 이익 기여가 높고, 경쟁 건강·다이어트 방송에서는 효능·후기 표현이 빈번하다. 두 분류는 동일하지 않으므로 개별 상품의 적합성을 추가 확인한다.
- 청소·생활 문제 해결 상품은 Before/After 시연을 통해 재현 가능한 판매 구조를 만들기 쉽다.
- 골프는 높은 이익률과 계절성을 활용하는 단기 수익 영역이다.
- 숙면·침구는 경쟁 노출이 강하지만 내부 실적이 부족한 White Space 실험 영역이다.
- Live Fashion·Beauty는 가격 확인과 공급처 검증을 보강하고, 라이브 참여·구매 전환으로 평가한다. TV 방송 근거 0건만으로 라이브 적합성이 낮다고 판단하지 않는다.

전달 메시지:

> 어떤 상품이 보이는지를 넘어, MediaWorks가 어디에 투자하고 어디는 작게 검증해야 하는지 구분할 수 있습니다.

메인 문서: [시장 기회 지도](./2026-09-04-mediaworks-data-insight-report.html#opportunity), [카테고리 실행안](./2026-09-04-mediaworks-data-insight-report.html#category-plan)

### 3. 카테고리마다 관찰되는 판매 방식이 다르다

아래는 방송에서 자주 관찰된 표현에 기반한 테스트 가설이다. 판매 성과와 연결해 검증한 성공 공식은 아니며, 표현 빈도만으로 최적 순서나 효과를 확정할 수 없다.

- 패션은 디자인과 착용 편의가 먼저다.
- 뷰티는 효능, 사용 시연, 후기와 안전성 근거가 중요하다.
- 건강 상품은 효능만이 아니라 후기·인증·지속 가능성을 함께 제시해야 한다.
- Home·Kitchen과 가전은 사용 전후 변화와 조작·세척·관리 불안 해소가 핵심이다.

전달 메시지:

> 이 데이터는 상품 선정뿐 아니라 방송 대본, 시연 순서, 반론 처리 방식까지 재사용할 수 있습니다.

메인 문서: [Broadcast DNA](./2026-09-04-mediaworks-data-insight-report.html#dna)

### 4. 제안하는 제품은 세 가지다

1. **Weekly Buyer Cockpit**: 매주 근거가 있는 후보 10개와 부족한 근거를 보여준다.
2. **Stored-only Product Finder**: 저장 근거로 순위를 산출하고 결과·근거·알고리즘 버전을 기록한다. 같은 입력 데이터와 알고리즘에서의 순위 재현성을 검증한다.
3. **Category Script DNA**: 카테고리별 판매 포인트, 증명 방식, 반론 처리 구조를 제공한다.

목표는 세 기능을 통해 발생한 판단과 판매 결과를 연결하는 것이다. 현재 코드에는 Finder UI·API·순위 계산·Run·Snapshot 저장과 관심/제외 기록이 있다. 샘플·방송·매출 연결, 이유 입력 의무화, 운영 배포와 실사용 검증은 별도로 확인·보완해야 한다.

전달 메시지:

> 핵심 제품은 AI 채팅 화면이 아니라, Buyer가 근거를 보고 판단하고 그 결과가 다시 학습되는 업무 시스템입니다.

메인 문서: [목표 운영 모델](./2026-09-04-mediaworks-data-insight-report.html#target-model)

### 5. 90일 동안 내부에서 먼저 증명한다

- 30일: 담당자와 3개 카테고리를 정하고 판단 기록을 시작한다.
- 60일: 구현된 Finder를 실사용 검증하고 판단 이유·샘플 결과 연결을 보완한다.
- 90일: 서로 다른 상품 100건의 판단 기록과 샘플·공급처 평가 등 중간 결과 20건을 제안 목표로 둔다. 판매 가설 1개를 정리한다.
- 3~6개월: 실제 판매·이익·반품·재주문 결과를 추적해 가설의 반복 성과를 검증한다. 90일 안에 수익 개선을 보장하지 않는다.
- 90일 후 `GO / HOLD / STOP`을 판단한다.

전달 메시지:

> 대규모 구축이나 SaaS 판매를 먼저 제안하는 것이 아니라, 90일 동안 업무 시간과 판단 품질의 변화를 측정하는 제안입니다.

메인 문서: [단계별 확장 계획](./2026-09-04-mediaworks-data-insight-report.html#expansion-roadmap), [90일 실행계획](./2026-09-04-mediaworks-data-insight-report.html#ninety-day-plan)

## 피해야 할 피칭

- **“AI가 잘 팔릴 상품을 자동으로 예측한다”**고 말하지 않는다.
- 경쟁사의 방송 횟수를 경쟁사 실제 매출로 설명하지 않는다.
- Product Finder는 코드 구현이 확인됐다. 운영 배포·사용자 검증·매출 연결까지 완료됐다고 설명하지 않는다.
- 모든 영상과 모든 카테고리를 전수 분석하겠다고 약속하지 않는다.
- 90일 검증 전에 외부 SaaS 판매나 다중 고객 확장을 제안하지 않는다.
- 데이터 양, 크롤링 기술, AI 모델 이름을 피치의 중심에 두지 않는다.

대신 다음처럼 표현한다.

> 자동 예측이 아니라, 근거를 구조화하고 사람이 더 빠르고 일관되게 판단하도록 지원합니다.

## 예상 질문과 답변

### “AI 추천을 믿을 수 있습니까?”

현재 추천을 그대로 믿으라는 제안이 아니다. 모든 추천에 출처, 반증, 부족한 근거, Snapshot ID를 표시하고 Buyer가 최종 판단한다. 현재 Snapshot은 표시된 결과의 근거를 추적한다. 전체 후보군과 당시 입력값까지 복원해 재계산하는 기능은 별도 검증 대상이며, Snapshot ID만으로 완전한 재현을 보장하지 않는다.

### “시간이 지나면 자동으로 더 똑똑해집니까?”

시간이나 데이터 수집만으로는 개선되지 않는다. 채택·거절 이유와 실제 샘플·방송·매출 결과가 누적되어야 MediaWorks에 맞는 판단 기준이 개선된다.

### “왜 경쟁 데이터 소스를 더 추가하지 않습니까?”

현재도 8,199개 후보와 2,561개 방송 분석이 있다. 지금의 병목은 데이터 부족이 아니라 상품 연결, 판단 기록, 결과 학습이다. 이 문제가 해결된 뒤 필요한 Source만 추가한다.

### “비용이 많이 증가하지 않습니까?”

현재 AI 비용보다 3.48TB 영상 저장과 2,600건 이상의 미완료 처리량이 더 큰 확장 위험이다. 전수 분석 대신 카테고리별 Quota와 대표 Sample을 적용하고, Backfill은 별도 Worker로 분리한다.

### “외부 고객에게도 판매할 수 있습니까?”

가능성은 있지만 지금은 아니다. 내부 효과와 판매 성과, Product Finder 실사용, 고객별 데이터 격리가 검증된 뒤 2개사 이내 Pilot으로 검증한다.

## 성과 측정과 제안 범위

- 시작 2주 동안 기존 방식의 후보 검토 시간, 검토 건수, 누락 근거를 기록한다. 이후 비슷한 카테고리·난이도 업무와 비교한다.
- 판단 100건은 고유 상품 기준으로 집계한다. 동일 상품의 클릭·상태 변경을 중복 집계하지 않는다.
- 중간 결과 20건은 샘플 평가 또는 공급 조건 확인이 끝난 고유 상품이다. 실제 판매 결과와 별도 집계한다.
- 기록률은 회의에서 검토한 상품 중 판단과 이유를 모두 기록한 상품의 비율이다. 기존 DB 0건만으로 기록률 0%를 산출하지 않는다.
- Pipeline 95%는 제안 운영 목표다. 합의한 작업의 기한 내 완료율로 측정하고 신규 작업과 과거 Backfill을 분리한다.
- 100건·20건은 운영을 정착시키기 위한 초기 목표이며 추천 정확도나 수익 효과를 통계적으로 보장하는 표본 수가 아니다.
- 고객에게 승인받을 범위는 주간 후보 검토, Finder 실사용, 결과 기록이다. 담당 인력·개발비·샘플/판매 실험비·운영비의 상한과 검수 항목을 합의한 후 일정을 확정한다.
- SaaS는 선택 가능한 후속 사업이다. 관심 고객 인터뷰는 병행할 수 있고, 외부 고객 데이터 투입은 격리 검증 후 진행한다.
