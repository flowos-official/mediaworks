# 2026-08-21 일본 피드백 미팅 준비안

## 1. 이번 미팅의 목표

이번 미팅은 “AI가 좋아졌다”는 설명이 아니라, 동일한 입력과 채점표로 기존 도구·ChatGPT/Gemini·개선 버전을 비교해 다음 단계의 계속/중단 조건을 합의하는 자리로 잡는다.

시간이 지나면 시스템이 자동으로 좋아진다는 표현은 사용하지 않는다. 실제 개선에는 아래 세 가지가 필요하다.

1. 일본 담당자가 정답·오답을 표시한 평가 데이터
2. 그 피드백을 검색 규칙, 프롬프트, 지식 자료에 반영하는 운영 절차
3. 같은 테스트 세트를 반복 측정하는 회귀 평가

## 2. 이번에 설명할 시스템 개선 내용

### 상품 검색

- 일본 서비스에서는 일본 데이터만 노출하도록 시장 경계를 적용했다.
- 가격, 카테고리, 채널 등 사용자가 지정한 필수 조건은 우선순위가 아니라 탈락 조건으로 처리한다.
- 조건을 충족하지 않는 상품으로 결과 수를 억지로 채우지 않는다. 결과가 적더라도 이유를 표시한다.
- 검색 결과의 출처, 가격, 카테고리 등 판단 근거를 확인할 수 있게 한다.
- 운영 DB의 일본용 검색 필드와 배포 코드의 호환성을 복구했다.

### 방송 대본 생성

- 기존 상품을 선택하더라도 바로 생성하지 않고 방송 시간, 타깃, 핵심 메시지, 실제 판매가, 시연 항목, 금지 표현, 톤을 먼저 받는다.
- 상품 설명·기능처럼 확인된 사실과 AI 조사·마케팅 아이디어 같은 기획 가설을 분리한다.
- 근거 없는 전문가, 고객 후기, 성능 수치, 가격, 혜택, 시연은 만들지 않는다.
- 현재 승인 대본 표본이 1건뿐이므로 그 상품의 고유 사실을 다른 상품에 복제하지 않고, 제한적인 진행 어휘만 참고한다.
- 생성 실패 시 무한 대기나 모호한 실패로 보이지 않게, 운영자가 조치할 수 있는 일본어 오류를 표시한다.

### 이번 단계에서 과장하면 안 되는 부분

- 아직 실제 고객 정답 세트로 검색 정확도가 검증된 것은 아니다.
- 승인 대본 표본이 1건이어서 “MWB 고유 문체를 학습했다”고 말할 수 없다.
- Gemini API 키가 현재 무효이므로 유효 키 교체 전에는 실제 생성 시연을 완료할 수 없다.
- 따라서 금요일에는 기능 설명보다 고객의 정답 데이터 확보와 평가 기준 합의가 우선이다.

## 3. 일본 측에 전달할 핵심 메시지

1. 피드백을 “모델 성능이 낮다”로만 해석하지 않고, 입력 조건·근거 데이터·평가 방식의 문제로 나눠 수정했다.
2. 범용 ChatGPT와의 차이는 문장 생성 자체가 아니라, 사내 상품 정보와 승인 규칙을 바탕으로 검색부터 대본 검토까지 재현 가능한 업무 흐름을 만드는 데 있다.
3. 이번에는 감상 평가를 반복하지 않고, 기존 도구와 동일한 문제로 블라인드 비교하자.
4. 월 10만 엔의 타당성은 모델 이름이 아니라 월간 사용량, 절감 시간, 채택률, 오류율로 판단하자.
5. 기준에 미달하면 추가 개발 범위와 비용을 다시 협의하거나 중단 조건을 명확히 하자.

## 4. 반드시 받아야 할 정보

### A. 상품 검색 정답 세트

최소 20건, 가능하면 최근 실무 검색 30건을 요청한다.

| 항목 | 받아야 하는 내용 |
|---|---|
| 실제 검색 문장 | 담당자가 평소 입력하는 일본어 원문 |
| 정답 상품 | 검색별 기대 상품 3~5개와 상품 URL/상품 코드 |
| 오답 사례 | 절대 나오면 안 되는 상품과 그 이유 |
| 필수 조건 | 가격 범위, 카테고리, 채널, 시즌, 타깃 등 반드시 지켜야 하는 조건 |
| 선호 조건 | 있으면 좋지만 결과 부족 시 완화 가능한 조건 |
| 기존 도구 결과 | 같은 검색어에 대한 기존 도구 상위 5개 결과와 담당자 평가 |
| 최종 업무 결과 | 실제 채택 여부와 채택하지 않은 이유 |

### B. 대본 기준 자료

| 항목 | 최소 요청량/내용 |
|---|---|
| 최종 승인 대본 | 서로 다른 상품군 5건 이상, 권장 10건 |
| 반려 초안 | 수정 전 초안과 최종본을 쌍으로 3건 이상 |
| 수정 이유 | 문장별 또는 구간별 수정 코멘트 |
| 프로그램 구조 | 총 방송 시간, 코너 순서, 역할, CTA 위치 |
| 상품 팩트시트 | 기능, 사양, 인증, 시험 결과와 각각의 출처 |
| 오퍼 정보 | 정상가, 방송가, 배송비, 보너스, 보증, 유효 기간 |
| 법무·방송 기준 | 금지 표현, 필수 고지, 사내 심의 체크리스트 |
| 타깃/핵심 메시지 | 주요 고객, 해결 과제, 반드시 전달할 한 문장 |
| 필수 시연 | 실제 가능한 시연과 불가능한 시연 |
| 경쟁 비교 기준 | 비교 가능한 항목과 사용하면 안 되는 표현 |

### C. 운영·가격 판단 자료

- 실제 사용자 수와 역할
- 월간 상품 검색 수와 대본 작성 수
- 현재 검색 1건·대본 1건에 걸리는 평균 시간
- 초안 채택률과 평균 수정 시간
- 기존 도구 및 범용 AI의 월 비용
- 허용 가능한 월 비용 범위
- 장애 대응 시간과 지원 언어에 대한 기대치
- 1개월 검증 후 계속 사용 여부를 판단할 수치 기준

## 5. 금요일 현장 평가 방법

### 검색 비교

- 고객이 제공한 사례 중 개발팀이 보지 않은 10건을 사용한다.
- 기존 도구와 개선 버전에 동일한 문장을 입력한다.
- 도구 이름을 가리고 상위 5개 결과를 담당자 2명 이상이 독립 채점한다.

| 지표 | 채점 방법 |
|---|---|
| 필수 조건 준수율 | 조건을 모두 충족한 결과 수 / 노출 결과 수 |
| Precision@5 | 정답으로 인정된 상품 수 / 최대 5개 |
| 유용 결과율 | 담당자가 후속 검토할 가치가 있다고 표시한 비율 |
| 치명적 오답 | 가격·카테고리·국가 등 필수 조건 위반 건수 |
| 근거 확인성 | 출처와 판단 근거를 확인할 수 있는지, 1~5점 |

검색의 1차 합격 기준은 “치명적 오답 0건”으로 합의하고, Precision@5 목표값은 일본 담당자와 현장에서 정한다.

### 대본 비교

- 서로 다른 상품군 2~3개를 사용한다.
- 동일한 팩트시트와 방송 조건을 개선 버전, ChatGPT/Gemini에 제공한다.
- 도구 이름을 가린 상태에서 담당자가 채점한다.

| 지표 | 채점 방법 |
|---|---|
| 사실 오류 | 출처 없는 수치·효능·가격·후기 수. 합격 기준 0건 |
| 방송 구성 적합도 | 실제 프로그램 흐름에 맞는지, 1~5점 |
| MWB 문체 적합도 | 승인 대본과 어조·전개가 맞는지, 1~5점 |
| 바로 사용 가능성 | 그대로 사용/경미 수정/대폭 수정/사용 불가 |
| 수정 시간 | 최종 승인본까지 실제 소요 분 |
| 심의 위험 | 금지 표현 또는 필수 고지 누락 건수 |

## 6. 60분 미팅 진행안

1. 5분: 받은 피드백에 대한 이해 확인
2. 10분: 수정 내용과 현재 한계 설명
3. 20분: 준비된 검색 5건 블라인드 비교
4. 15분: 대본 1건 비교 및 수정 포인트 기록
5. 10분: 추가 자료 제공 담당자·기한·1개월 합격 기준 합의

## 7. 회의에서 확정할 결정 사항

- 검색 정답 세트 제공 담당자와 제공일
- 승인/반려 대본 및 팩트시트 제공 범위
- 검색과 대본의 수치 합격 기준
- 검증 기간과 대상 사용자 수
- 데이터 반영 주기 및 일본 측 승인 담당자
- 다음 개발 범위, 비용, 계속/중단 결정일
