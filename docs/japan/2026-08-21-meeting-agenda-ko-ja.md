# MediaWorks 일본 협업 미팅 아젠다

- 일시: 2026년 8월 21일
- 권장 시간: 90분
- 목적: 현재 시스템의 성과와 한계를 사실 기반으로 확인하고, 일본 측 기존 플랫폼 경험과 실제 사용자 피드백을 반영한 다음 협업 체계·필요 리소스·일본 전담 인력 운영안을 확정한다.

## 1. 이번 회의에서 얻어야 할 결과

회의가 끝날 때 아래 사항을 문서로 확정한다.

1. 우선 수정할 사용자 문제와 합격 기준
2. 일본 측이 제공할 검색 정답·승인 대본·기존 플랫폼 자료의 담당자와 기한
3. 한국 개발팀과 일본 운영팀의 역할 분담
4. 4주 검증 기간의 사용자, 범위, 측정 지표
5. 일본 현지 전담 인력의 역할, 채용 형태, 예산, 채용 일정
6. 다음 투자·계약·계속 또는 중단 판단일

| 순서 | 아젠다 | 시간 | 핵심 결과 |

## 3. 아젠다별 상세 내용

### 3-1. 사내 직원들의 실제 사용 피드백 상세 공유

#### 일본 측에 요청할 공유 방식

“정확도가 낮았다”와 같은 총평만 받지 않고 실제 사례 단위로 확인한다.

| 항목 | 확인할 내용 |
|---|---|
| 사용자 | 소속, 역할, AI 및 기존 도구 사용 경험 |
| 수행 업무 | 상품 검색, 상품 검토, 대본 초안, 심의 등 |
| 실제 입력 | 사용자가 입력한 일본어 원문과 선택 조건 |
| 실제 결과 | 시스템이 보여준 상품 또는 대본 |
| 기대 결과 | 사용자가 원했던 상품·문장·구성 |
| 문제 유형 | 오답, 누락, 느림, 사용성, 설명 부족, 심의 위험 |
| 빈도·영향 | 몇 번 발생했고 업무에 어느 정도 영향을 줬는지 |
| 현재 대안 | 기존 도구, ChatGPT, Gemini 또는 수작업 처리 방식 |
| 최종 행동 | 결과 채택·수정·폐기 여부와 수정 시간 |

#### 회의에서 물어볼 질문

- 가장 업무를 방해한 문제 3가지는 무엇인가?
- 결과가 좋았던 사례도 있었는가? 있었다면 어떤 조건이 달랐는가?
- 검색 결과가 3개뿐이어도 정확한 것이 좋은가, 정확도가 낮더라도 10개가 필요한가?
- 대본 품질을 판단할 때 문체, 사실 정확성, 구성, 작성 시간 중 무엇이 가장 중요한가?
- ChatGPT/Gemini에서 반복해서 사용하는 프롬프트나 사내 자료가 있는가?
- 어느 정도 수정이면 “사용 가능한 초안”으로 인정하는가?

#### 받아야 할 원본 자료

- 실제 검색 사례 최소 20건과 검색별 정답 상품 3~5개
- 기존 도구와 MediaWorks의 동일 검색 결과
- 최종 승인 대본 5건 이상, 권장 10건
- 수정 전 초안과 최종본 및 수정 코멘트 3세트 이상
- 가능하면 실제 사용 화면 녹화 또는 화면 캡처

#### 이 세션의 결정 사항

- 우선 해결할 문제 3개
- 검색과 대본의 정량 합격 기준
- 검증용 사례 중 개발팀에 공개할 학습 세트와 비공개 평가 세트

### 3-2. MediaWorks 개발 및 진행 현황 공유

#### 우리가 공유할 내용

- 일본 서비스와 타 시장 데이터의 노출 경계 적용
- 검색의 가격·카테고리·채널 등 필수 조건 위반 상품 배제
- 조건에 맞지 않는 결과로 개수를 억지로 채우지 않는 방식
- 대본 생성 전 방송 시간, 타깃, 핵심 메시지, 실제 판매가, 시연, 금지 표현, 톤 입력
- 확인된 상품 사실과 AI 조사·기획 가설의 분리
- 근거 없는 성능 수치, 가격, 후기, 전문가, 혜택 생성 방지
- AI 실패 사유의 일본어 표시 및 운영 DB 기록
- Vercel Production 배포, DB 마이그레이션, 빌드·회귀 테스트 완료

#### 반드시 함께 설명할 한계

- 고객 정답 세트가 아직 없어 실제 검색 정확도 향상 폭은 검증 전이다.
- 승인 대본이 현재 1상품뿐이어서 MWB 고유 문체를 충분히 모델링했다고 할 수 없다.
- 이용 기간만으로 AI가 자동 학습되는 구조는 아니다. 담당자의 정답 표시와 정기 반영 과정이 필요하다.
- 현재 Gemini API 키가 무효이므로, 미팅 전 유효 키 교체와 실제 생성 E2E 검증이 필요하다.

#### 보여줄 데모

1. 실제 일본어 조건으로 상품 검색
2. 필수 조건 위반 상품이 제외되는지 확인
3. 상품 선택 후 방송 조건 입력
4. 생성 대본의 사실 근거와 금지 표현 확인
5. 오류 발생 시 운영자 안내 확인

#### 이 세션의 결정 사항

- 현재 개발 범위에 대한 이해 일치 여부
- 금요일 이후 즉시 수정할 항목과 별도 견적이 필요한 신규 기능 구분

### 3-3. 지난 1.5년간 타 업체와 구축·진행한 플랫폼 정보 공유

이 내용은 경쟁사 정보 확인이 목적이 아니라, 이미 투자한 자산을 재사용하고 같은 실패를 반복하지 않기 위한 것이다.

#### 일본 측에 요청할 정보

| 구분 | 확인할 내용 |
|---|---|
| 도입 목적 | 처음 해결하려 했던 업무 문제와 기대 성과 |
| 개발 범위 | 검색, 데이터 수집, 분석, 대본, 승인, 관리 기능 |
| 실제 사용 현황 | 현재 사용자, 사용 빈도, 실제 업무 적용 범위 |
| 성과 | 잘 작동한 기능, 절감 시간, 채택률, 정성적 평가 |
| 문제 | 사용이 중단되거나 불편했던 이유와 미해결 과제 |
| 검색 방식 | 데이터 출처, 검색 조건, 랭킹 기준, 기존 도구의 강점 |
| AI 방식 | 사용 모델, 프롬프트, 사내 지식 연결, 피드백 반영 방식 |
| 데이터 자산 | 상품 DB, 승인 대본, 방송 이력, 사용자 피드백, 평가 세트 |
| 시스템 구조 | 기술 스택, 외부 서비스, 운영·장애 대응 방식 |
| 권리 관계 | 소스 코드, 데이터, 프롬프트, 계정, 산출물의 소유·사용 권한 |
| 계약·비용 | 초기 비용, 월 운영비, 추가 개발비, 계약상 제약 |
| 접근 가능 범위 | 문서, API, 데이터 내보내기, 관리자 권한 제공 가능 여부 |

#### 반드시 확인할 질문

- 기존 플랫폼의 “검색 정확도가 더 높다”는 판단 근거와 평가 사례가 있는가?
- 기존 플랫폼의 검색 결과를 API·CSV 등으로 비교 평가에 활용할 수 있는가?
- 지난 1.5년간 축적된 데이터 중 MWB가 소유하고 우리 시스템에서 사용할 수 있는 범위는 어디까지인가?
- 기존 업체와의 계약에서 데이터 이전, 소스 사용, 비밀유지 관련 제한이 있는가?
- 기존 플랫폼에서 유지해야 할 기능과 과감히 폐기해도 되는 기능은 무엇인가?
- 비용이나 개발 속도보다 실제로 가장 불만이었던 운영 문제는 무엇인가?

#### 이 세션의 결정 사항

- 재사용 가능한 데이터·문서·API 목록
- 기존 업체 확인 또는 동의가 필요한 항목
- 기존 시스템 유지, 연동, 단계적 교체 중 권장 방향

### 3-4. 향후 협업 및 리소스 조율

#### 권장 운영 방식: 4주 공동 검증

| 주차 | 한국 개발팀 | 일본 운영팀 | 공동 결과물 |
|---|---|---|---|
| 1주차 | 평가 환경과 기록 방식 정리 | 검색·대본 정답 자료 제공 | 기준선 및 합격 기준 |
| 2주차 | 우선순위 오류 수정 | 실제 사용자 2~3명 테스트 | 사례별 피드백 목록 |
| 3주차 | 검색·대본 품질 조정 | 기존 도구와 블라인드 비교 | 중간 평가 결과 |
| 4주차 | 회귀 테스트 및 운영 정리 | 최종 사용자 평가 | 계속·추가 개발·중단 결정 |

#### 역할 분담안

| 업무 | 한국 개발팀 | 일본 운영팀 | 일본 전담 인력 |
|---|---|---|---|
| 제품 개발·배포 | 책임 | 의견·승인 | 요구사항 정리 |
| 검색·대본 정답 판정 | 기술 지원 | 최종 책임 | 자료 수집·품질 확인 |
| 사용자 교육 | 자료 제작 | 참석자 지정 | 일본어 교육 진행 |
| 장애 대응 | 원인 분석·수정 | 현상 및 재현 정보 제공 | 1차 접수·상태 안내 |
| 영업·데모 | 기술 지원 | 관계 형성 | 일본어 제안·데모 책임 |
| KPI 보고 | 기술 지표 제공 | 업무 성과 확인 | 통합 보고 |

#### 리소스 협의 항목

- 양측 프로젝트 책임자 각 1명
- 일본 측 실제 사용자 2~3명
- 검색 및 대본 최종 판정자 각 1명
- 주 1회 45분 정기 회의
- 피드백 제공 후 2영업일 내 우선순위 분류
- 긴급·일반·개선 요청의 대응 시간 구분
- 추가 개발의 포함 범위와 별도 견적 기준

#### 성과 판단 지표

- 검색 필수 조건 위반 건수
- 검색 상위 5개 정답률과 실무 검토 가치 비율
- 대본의 근거 없는 사실 및 심의 위험 건수
- 초안 채택률과 최종 승인까지의 수정 시간
- 실제 주간 사용자 수와 반복 사용률
- 검색 1건·대본 1건당 절감 시간

### 3-5. 일본 현지 전담 인력 채용

#### 권장 직무

단순 영업직보다 일본어·한국어가 가능하고 AI 제품 이해, 고객 요구사항 정리, 교육, 운영을 함께 수행하는 `일본 솔루션 컨설턴트 / Customer Success` 역할이 우선 필요하다.

#### 주요 업무

- 일본 고객과 한국 개발팀 사이의 요구사항 번역 및 우선순위 정리
- 고객 미팅, 제품 데모, 제안서 및 도입 지원
- 사용 교육과 초기 문의 대응
- 검색 정답, 승인 대본, 반려 이유 등 품질 개선 자료 수집
- 주간 KPI와 장애 상태 보고
- 업종별 AI 패키지 및 일본 시장 메시지 검증
- 외부 영업 기회 발굴과 도입 후 고객 유지 관리

#### 필수 역량

- 비즈니스 수준의 일본어와 한국어
- 일본 기업 대상 B2B 커뮤니케이션 경험
- 생성형 AI, SaaS 또는 소프트웨어 제품을 설명할 수 있는 수준의 기술 이해
- 고객의 모호한 피드백을 재현 사례와 합격 조건으로 바꿀 수 있는 능력
- 문서화, 일정 관리, 후속 조치 역량

#### 권장 채용 방식

초기에는 2~3개월 계약직 또는 업무 위탁으로 검증하고, 고객 파이프라인과 운영량이 확인된 후 정규직 전환을 검토한다.

#### 초기 KPI 예시

- 사용자 피드백의 재현 정보 완성률
- 요청 접수 후 2영업일 내 분류율
- 주간 활성 사용자 및 반복 사용률 개선
- 데모 이후 검증 프로젝트 전환 수
- 검증 프로젝트 이후 유료 전환율
- 고객 문의의 1차 응답 시간

#### 회의에서 확정할 내용

- 채용 주체와 보고 라인
- 근무 지역, 근무 형태, 필요 출장 범위
- 계약직·위탁·정규직 중 초기 채용 방식
- 예산 범위와 인센티브 구조
- 영업 중심인지 운영·고객 성공 중심인지 우선순위
- 후보자 탐색 담당자와 채용 목표일
- 채용 전까지 일본 측 임시 담당자

## 3. MediaWorksの開発・進行状況

### ご説明する内容

- 日本向けサービスにおける市場データの表示範囲整理
- 価格、カテゴリー、チャネル等の必須条件に反する商品の除外
- 条件外の商品で検索件数を埋めない仕組み
- 台本生成前の放送時間、ターゲット、主要メッセージ、実売価格、実演、禁止表現、トーンの入力
- 確認済みの事実と、AI調査による企画仮説の分離
- 根拠のない数値、価格、お客様の声、専門家、特典の生成防止
- AI処理失敗時の日本語エラー表示
- Production環境、データベース、ビルド、回帰テストの状況

### 現時点の制約

- 御社の正解データによる検索精度の比較検証はこれからです。
- 承認台本のサンプルが1商品分のため、御社固有の表現を十分に再現できる段階ではありません。
- 利用期間だけでAIが自動的に改善されるわけではなく、正解判定と定期的な反映が必要です。
- 現在のGemini APIキーは無効であるため、有効なキーへの変更後に生成機能の最終確認が必要です。
